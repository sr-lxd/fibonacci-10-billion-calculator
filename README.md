# 用家用电脑计算第 100 亿项斐波那契数

这个项目用 Python 计算斐波那契数列第 100 亿项，并把完整十进制结果写入文件。实测机器使用 32 GB 内存，在 Windows 11 + WSL2 Ubuntu 24.04 环境下，从计算到写盘共用时 9 分 41 秒，结果有 2,089,876,403 位。

这件事的难点不只在于找到一个快速算法。快速倍增把计算压缩到几十层之后，真正决定任务能否完成的，是大整数库的实现边界、内存峰值、十进制转换和磁盘写入。对这个规模来说，算法是起点，工程才是能否跑通的关键。

## 实测结果

| 项目 | 结果 |
|---|---:|
| 目标 | F(10,000,000,000) |
| 十进制位数 | 2,089,876,403 位 |
| Fibonacci 大整数运算 | 53.6 秒 |
| 十进制转换与写盘 | 527.8 秒 |
| 总时间 | 581.4 秒（9 分 41 秒） |
| 峰值内存 | 约 5 GiB |
| 实测环境 | 32 GB 内存，Windows 11 + WSL2 Ubuntu 24.04 |

结果以 `14135` 开头，以 `46875` 结尾。完整复现步骤、硬件细节和实验记录见[详细说明](./如何使用家用电脑计算第100亿项斐波那契数列值.md)。完整结果约 2.09 GB，不放在 GitHub 仓库中。

## 计算原理

朴素递归需要约 O(φⁿ) 次调用，算到很小的 n 就会变得不可行。脚本改用按 n 的二进制位推进的倍增算法。每层从两个相邻 Fibonacci 状态出发，通过平方和加减得到下一个两倍下标附近的状态，因此 F(10¹⁰) 只需约 33 层，而不需要逐项计算 100 亿次。

脚本的“两平方”后端每层计算 `F(k)²` 和 `F(k−1)²`，再用 Fibonacci 恒等式组合出 `F(2k−1)`、`F(2k)` 和 `F(2k+1)`。计算过程只保留当前层需要的大整数，不缓存整条递推历史。自动后端在 `n ≤ 4,294,967,294` 时调用 `gmpy2.fib`；超过这个接口范围后切换到 Python 层的两平方实现。这个下标接口范围与下文提到的约 4 GiB 缓冲区问题是两件不同的事。

## Windows 的约 4 GiB 边界

在本项目的大数据实测中，Windows 构建的 GMP 在超大 FFT 运算中会遇到约 4 GiB 的内部缓冲区大小计算边界。Windows 使用 LLP64 数据模型，相关构建路径中的 `long` 为 32 位；当缓冲区尺寸越过边界时，大小计算会溢出并导致 GMP 分配失败。即使系统仍有可用内存，这个实现边界也可能让运算中止。

这不是“Windows 最多只能使用 4 GB 内存”，也不等于机器物理内存不足。项目对照测试发现，同一台电脑上的 WSL2 Ubuntu 使用 LP64 数据模型，Linux 构建的 GMP 可以正确处理这类大尺寸，因而绕过了这次遇到的 Windows ABI 边界。WSL/Linux 仍需要足够的内存、提交空间和磁盘空间；它绕过的是特定的实现限制，不是所有资源限制。

因此，项目让 Windows 原生界面负责交互与小规模计算，让 WSL2/Linux 负责超大规模的 GMP 运算。计算放在独立 worker 进程中。若 GMP 硬退出，界面仍能保留诊断结果，并记录每层运算、内存和失败位置。

## 十进制输出也是主要工程工作

F(10¹⁰) 的二进制整数约 868 MiB，转成十进制后有约 2.09 GB 文本。实测中，转换和写盘用了 527.8 秒，远长于 53.6 秒的大整数计算。

脚本用 256 位 MPFR 精度按对数公式计算精确位数，避免先构造同等规模的十进制幂。输出时使用分治转换：把大整数拆为高位块和低位块，递归处理到 400 万位叶块，再直接写入文件。这样无需在内存中同时保留完整的 20.9 亿字符字符串。

## 运行环境

- 64 位 Windows；超大规模计算使用 WSL2 Ubuntu。
- Windows Python 3.13、`gmpy2` 和 `psutil` 用于界面、资源监控及小规模计算。
- WSL Ubuntu 安装 `python3-gmpy2`；中文 GUI 字体可安装 `fonts-noto-cjk`。
- 建议先运行较小规模验证环境，再尝试 10 亿、20 亿、40 亿，最后运行 100 亿。

程序安装、完整命令、诊断模式和结果校验方法见[详细说明](./如何使用家用电脑计算第100亿项斐波那契数列值.md)。仓库忽略计算输出文件与诊断日志，避免把超大结果或本地运行数据加入版本控制。

## Windows 简易图形界面 v1.2.0

项目提供 [单文件 GUI 程序](./fib_mpir_gui_v1.2.0.exe)。双击后可输入下标、选择结果文件位置，并查看计算阶段、十进制写盘比例和运行记录。窗口可以停止运行中的计算；停止后结果文件可能不完整，需要手动删除。窗口和程序文件均使用仓库中的 `s2.ico` 图标。

GUI 将 MPIR v1.1.0 引擎打包在单个 EXE 内，Windows x64 用户无需安装 Python、Tkinter 或 MPIR。程序默认建议计算 F(10,000,000,000)，该结果约 2.09 GB；开始前请在界面选择有足够空间的磁盘。计算层数不是时间百分比，只有十进制转换阶段会显示真实的写盘比例。

便携运行：下载 `fib_mpir_gui_v1.2.0.exe` 后双击即可。源码运行可用 Python 3.10 或更新版本执行 `python fib_mpir_gui_v1.2.0.py`，并将 `fib_mpir_v1.1.0.exe` 放在脚本同一目录。

## MPIR 原生 C 版本

项目提供 [fib_mpir.c](./fib_mpir.c) 和已编译的 [Windows x64 v1.1.0 程序](./fib_mpir_v1.1.0.exe)。程序使用 MPIR 的 GMP 兼容 mpz 接口、两平方 Fibonacci 递推和分治十进制写盘。输入下标使用 64 位整数，不调用 Win64 下参数只有 32 位的 mpz_fib_ui。

v1.1.0 由 Visual Studio 2019 x64 编译，并静态链接 MPIR。依赖检查显示它只依赖 Windows 自带的 KERNEL32.dll；Windows x64 用户无需另装 MPIR DLL 或 VC++ 运行库。仓库保留了旧版 fib_mpir.exe（v1.0.0）；升级版使用带版本号的文件名。obj 是编译中间文件，运行程序不需要它。

v1.1.0 增加运行提示：启动时显示版本和目标文件；大整数计算期间每 10 秒报告当前层数；十进制转换和写盘期间每 10 秒报告已处理位数及百分比；结束时显示总用时。计算层数不代表时间百分比，因为后几层的运算量更大。

验证记录：v1.0.0 已完成 F(10,000,000,000)，报告 2,089,876,403 位；输出长度、开头和末尾数字与已知值相符。v1.1.0 已在同一 MPIR 库上成功编译，尚未运行计算验证。完整数字仍应与独立实现逐位或通过标准化后的 SHA-256 进一步核对。

### 直接运行

在命令提示符进入程序所在目录，先运行小规模验证：

    fib_mpir_v1.1.0.exe --version
    fib_mpir_v1.1.0.exe 100 F_100.txt
    type F_100.txt

目标规模运行命令：

    fib_mpir_v1.1.0.exe 10000000000 F_10000000000.txt

完整十进制结果约 2.09 GB。开始前确认目标磁盘至少有 3 GB 可用空间，并为运算保留足够内存。输出文件匹配 F_*.txt，已由 Git 忽略。

### 从源码构建

Windows 原生 Visual Studio 工程使用 [Brian Gladman 的 MPIR Windows 仓库](https://github.com/BrianGladman/mpir)。wbhart/mpir 源码仓库没有本项目所需的 Visual Studio 工程目录。

在 Visual Studio x64 Native Tools 命令提示符中执行：

    git clone --depth 1 https://github.com/BrianGladman/mpir.git C:\Users\lusun\mpir-win-src
    cd /d C:\Users\lusun\mpir-win-src
    msbuild msvc\vs19\lib_mpir_gc\lib_mpir_gc.vcxproj /m /p:Platform=x64 /p:Configuration=Release

构建后，头文件和静态库位于 MPIR 源码下的 lib\x64\Release。回到本项目目录编译：

    cl /O2 /W4 /I"C:\Users\lusun\mpir-win-src\lib\x64\Release" /Fofib_mpir_v1.1.0.obj fib_mpir.c /link /OUT:fib_mpir_v1.1.0.exe /LIBPATH:"C:\Users\lusun\mpir-win-src\lib\x64\Release" mpir.lib

先验证 F(100)，再逐步增大 n。判断其他机器上的构建能否完成大数计算，需要按相同流程实测，并核对位数、首尾数字及独立计算结果。
